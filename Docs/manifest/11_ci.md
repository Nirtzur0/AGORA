## Release/Promotion Trigger Paths

`AR-C04` + `AR-C05` are implemented in `.github/workflows/ci.yml`:

- `cmd-13-nightly-full-suite`:
  - trigger: nightly schedule (`0 7 * * *`) + `workflow_dispatch` (`run_full_e2e=true`, optional `observability_sink_mode`/`observability_sink_url`)
  - runbook mapping: `CMD-13`
  - purpose: maintain fresh full-e2e confidence for release promotion with warning-noise guardrails plus runtime/flake policy enforcement.
- `sink-evidence-recency-gate`:
  - trigger: weekly Monday UTC schedule (`0 8 * * 1`) + `workflow_dispatch` (`run_sink_recency_gate=true`)
  - runbook mapping: `CMD-41`
  - purpose: enforce standing recency governance independent of sink-routing code-change guardrails.
- `release-tag-gate`:
  - trigger: `push` on `v*` tags + `workflow_dispatch` (`run_release_gate=true`, optional `observability_sink_mode`/`observability_sink_url`)
  - runbook mapping: `CMD-11`, `CMD-25`, `CMD-27`, `CMD-13`, `CMD-37`, `CMD-38`
  - purpose: fail-closed release validation before release publication, including full-e2e warning-budget + runtime/flake policy enforcement.
- `objective-metrics-gate`:
  - trigger: PR/push by default, plus `workflow_dispatch` (`run_objective_gate=true`, optional `observability_sink_mode`/`observability_sink_url`)
  - runbook mapping: `CMD-24` + `CMD-29` + `CMD-32` (+ sink publish path `CMD-40`)
  - purpose: capture objective/snapshot remote active sink evidence without invoking full nightly/release gates.

## External Sink Routing Plan (`AR-C12`, `AR-C13`, `AR-C14`, `AR-C15`, `AR-C16`, `AR-C17`)

Status: implemented with gate-class sink failure-mode policy.

Planned external-routing payload sources:

- `objective-metrics-gate` output bundle (`CMD-29`):
  - `Docs/implementation/reports/objective_metrics_latest.json`
  - `Docs/implementation/reports/objective_metrics_history.jsonl`
- `objective-metrics-gate` observability snapshot bundle (`CMD-32`):
  - `Docs/implementation/reports/observability_snapshot_latest.json`
  - `Docs/implementation/reports/observability_snapshot_dashboard.md`
- heavy-gate trend bundles (`CMD-39`):
  - `cmd-13-nightly-runtime-trend`
  - `release-tag-gate-artifacts` (`release-tag-runtime-trend-*`)

Delivery policy:

1. `workflow_dispatch` now accepts:
   - `run_objective_gate` (`false`, `true`)
   - `run_sink_recency_gate` (`false`, `true`)
   - `observability_sink_mode` (`disabled`, `dry_run`, `active`)
   - `observability_sink_url` (optional override; fallback to `OBSERVABILITY_SINK_URL` secret)
2. Publish steps continue to run with `--fail-open true` so source-of-truth in-repo evidence is always produced.
3. `AR-C13` governance posture by gate class:
   - `objective-metrics-gate`: governance fail-closed for release readiness (failed/missing sink publish blocks sign-off until rerun evidence exists).
   - `cmd-13-nightly-full-suite`: fail-open operability signal (SEV-2 triage, no direct release block).
   - `release-tag-gate`: governance fail-closed for release cut (failure requires rerun success or explicit emergency waiver with fallback evidence).
4. In-repo artifacts remain authoritative fallback during sink outages.
5. Sink-routing changes are freshness-guarded in CI docs checks (`AR-C15`) so stale evidence references cannot merge unnoticed.

Periodic recency policy enforcement (`AR-C17`):

1. Standing recency thresholds are automated via `CMD-41` (`objective<=14d`, `nightly<=7d`, `release-tag<=30d`).
2. Weekly governance check runs in CI via `sink-evidence-recency-gate` (Monday UTC, cron `0 8 * * 1`).
3. Release sign-off enforces the same policy in `release-tag-gate` before heavy release commands execute.
4. Waiver model remains capped at 72 hours and requires explicit release-owner + maintainer-on-call acknowledgement in release/status docs.

Ownership and escalation references:

- `Docs/manifest/07_observability.md`
- `Docs/reference/release_workflow.md`
