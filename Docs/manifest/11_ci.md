# CI

CI is implemented via GitHub Actions in `.github/workflows/ci.yml`.

## Current Jobs

- `docs-guardrail`: on PRs, enforces that changes to tests/CI/runtime also update:
  - `Docs/implementation/00_status.md`
  - `Docs/implementation/checklists/04_test_stabilization.md`
- `check-stubs`: rejects TODO markers and bare `pass` statements in production directories.
- `smoke-test`: boots docker compose infra, starts Core API, and checks `/health`.

## Desired Mapping (Test Stabilization)

During test stabilization we keep a clear mapping between CI and local commands:

- Unit tests: `make test-unit`
- Integration tests: `make test-integration` (requires docker compose infra)
- E2E: optional / opt-in (`make test-e2e`)

## Guardrail Requirement

Any PR that changes tests, CI config, or runtime behavior must also update:

- `Docs/implementation/00_status.md`
- `Docs/implementation/checklists/04_test_stabilization.md`

The stabilization process should add a CI guardrail check to enforce this (see checklist).
This is enforced in CI via the `docs-guardrail` job in `.github/workflows/ci.yml`.
