# Epic: UI Audit and Release Discipline

## Goal

Improve AGORA's user-facing audit workflows in two ways:
- keep deterministic UI verification healthy
- produce a maintainers-first redesign and design-system handoff that can drive a later implementation packet

## User Stories

- As a reviewer, I need stable UI flows for project/workspace audit tasks.
- As a maintainer, I need a repeatable release-readiness path tied to canonical commands.
- As a maintainer, I need the dashboard to surface blockers, gate readiness, and provenance hotspots before raw ledgers.
- As a reviewer, I need investigation, research-record review, and governance to feel like coherent workflows instead of separate tabs.

## Tasks

- Expand/maintain E2E checks for key UI pages.
- Audit the current AGORA UI and identify structural, interaction, and information-design weaknesses.
- Produce a Figma redesign direction with implementation-realistic capture routes and design-system foundations.
- Write implementation-aware handoff docs covering screens, components, route structure, and states.
- Align CI jobs with runbook command IDs.
- Create and enforce release-readiness checklist artifacts.
